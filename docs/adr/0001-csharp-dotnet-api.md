# 0001. C# / ASP.NET Core for the API

- **Status:** Accepted
- **Date:** 2026-11-04
- **Deciders:** Bill Puccio

## Context

The API is the center of Foreman. It is the system of record for customers, jobs, the price book and quotes. It enforces the human approval gate on quotes. It also runs Foreman's conversation loop: it calls the model, acts as the MCP client, and feeds tool results back.

That job needs a typed language with good async support, mature HTTP and data-access libraries, and a first-class MCP SDK. The repo is also a portfolio piece meant to be productionizable into Blue Collar Workflows later, so the stack should be one that a small business platform could run for years.

## Decision

Build the API in **C# on the current .NET LTS release** (.NET 10 at the time of writing) using **ASP.NET Core minimal APIs**, organized with route groups per resource (`/customers`, `/jobs`, `/quotes`, `/foreman`).

Baseline conventions:

- Endpoints stay thin and delegate to application services, so business rules (especially the approval gate) are testable without HTTP.
- Errors are returned as RFC 9457 `ProblemDetails`.
- Structured logging through `ILogger`, with every Foreman tool call logged.
- OpenAPI document generated by the framework, with Swagger UI in development.
- `/health` endpoint via ASP.NET Core health checks.
- Tests use xUnit, with `WebApplicationFactory` for integration tests.
- Configuration and secrets come from environment variables and user secrets. No real keys are committed.

## Consequences

- One language for the API and (per [ADR-0002](0002-mcp-server-language-and-transport.md)) the MCP server, so domain types and data access can be shared.
- Minimal APIs keep the surface small and readable for a demo. If the endpoint count grows a lot, route groups can be split into separate files without switching to controllers.
- The iOS app talks to the API over HTTPS with JSON. The OpenAPI document is the contract between them.
- Contributors need the .NET SDK installed, or can use the Docker setup planned in BCW-47.
- Moving to the next LTS is an expected, low-risk upgrade and doesn't need a new ADR.

## Alternatives considered

- **Node.js / TypeScript (Express or Fastify):** strong MCP ecosystem, but it doesn't show the C# / .NET skill set this repo is meant to demonstrate, and the type system is weaker at runtime boundaries.
- **Python (FastAPI):** fast to prototype and good for AI work, but a weaker fit for a long-lived typed business backend.
- **ASP.NET Core controllers:** fully supported, but more ceremony than this API needs.
